<threat_model>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> /verify-otp and /verify-otp/resend | Untrusted OTP submissions and resend requests cross into auth state changes |
| auth route -> otp_challenges table | Session-bound challenge state transitions are persisted server-side |
| auth route -> Resend delivery service | OTP delivery crosses a service boundary before the challenge swap completes |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-22-01 | T | resend policy enforcement | mitigate | Enforce cooldown and cap from server-side `OtpChallenge.issued_at` history and config values, not client timers |
| T-22-02 | D | /verify-otp/resend | mitigate | Deny resend when cooldown or window cap is exceeded and preserve the current active challenge until replacement send succeeds |
| T-22-03 | I | verify template and flash messages | mitigate | Keep all resend/verify messages generic in Vietnamese and never expose OTP values or provider internals |
</threat_model>
