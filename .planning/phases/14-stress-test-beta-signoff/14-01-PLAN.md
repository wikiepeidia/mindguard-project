# Phase 14 Plan 01: Stress Test with Locust & Beta Sign-off

**Phase Goal:** Team biết chính xác ngưỡng CCU tối đa và có bằng chứng hệ thống sẵn sàng cho Beta 1.

## Tasks

### Task 1: Install Locust & Create Test Infrastructure

**What:** Add locust to requirements.txt and create the locustfile with weighted user scenarios.

**Files to create/modify:**

- `requirements.txt` — add `locust>=2.32`
- `tests/stress/locustfile.py` — Main load test file

**locustfile.py structure:**

```python
from locust import HttpUser, task, between, SequentialTaskSet

class MindGuardUser(HttpUser):
    wait_time = between(1, 5)
    
    # Weighted tasks matching CONTEXT.md behavior mix:
    # Homepage 30%, Leaderboard 10%, Quiz 20%, Report 10%,
    # Chatbot 15%, Library 10%, API 5%
    
    @task(30)
    def browse_homepage(self): GET /
    
    @task(10)
    def view_leaderboard(self): GET /leaderboard
    
    @task(20)
    def quiz_flow(self): GET /quiz (sequential steps)
    
    @task(10)  
    def view_report_form(self): GET /scammer/report
    
    @task(15)
    def chatbot_send(self): POST /chatbot/send (with auth)
    
    @task(10)
    def browse_library(self): GET /library
    
    @task(5)
    def api_check(self): GET /api/v1/check?q=test
```

**Authentication:** `on_start()` method registers a test user and logs in, stores session cookie for authenticated endpoints.

**Acceptance:**

- `locust --version` works after install
- locustfile imports without error

### Task 2: Run Stress Test Against Production

**What:** Execute locust in headless mode with staged ramp-up against `https://mindguard-five.vercel.app`.

**Command:**

```bash
locust -f tests/stress/locustfile.py \
  --host https://mindguard-five.vercel.app \
  --headless \
  --users 200 \
  --spawn-rate 10 \
  --run-time 10m \
  --html tests/stress/report.html \
  --csv tests/stress/results
```

**Ramp stages:**

- 0→50 users: 5s spawn rate (baseline)
- 50→100: sustained moderate
- 100→200: stress zone
- Monitor for error rate crossing 5%

**Acceptance:**

- Test runs to completion (or stops at failure threshold)
- HTML report generated
- CSV data captured

## Threat Model

| Threat | Mitigation |
|--------|-----------|
| Stress test triggers Vercel abuse detection | Use reasonable spawn rate (10/s), respect rate limits, add think time |
| Test creates junk data in production DB | Use dedicated test user prefix, clean up in `on_stop()` |
| Rate limiter blocks all test traffic from same IP | Design tasks with realistic wait_time (1-5s), stay within per-user limits |
| NeonDB connection pool exhaustion | Monitor for 5xx errors indicating DB issues |
