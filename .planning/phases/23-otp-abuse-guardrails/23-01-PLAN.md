## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> /verify-otp and /verify-otp/resend | Untrusted OTP submissions and resend requests can attempt brute-force or burst abuse |
| auth routes -> anti_spam_events / anti_spam_actor_states | Security telemetry is persisted for future cooldown enforcement |
| auth routes -> otp_challenges | Abuse cooldown is synchronized back onto the active OTP challenge state |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-23-01 | D | `/verify-otp` POST | mitigate | Add config-backed route-level limiter and block repeated bursts with HTTP 429 before repeated processing continues |
| T-23-02 | T | OTP abuse telemetry actor identity | mitigate | Derive a stable actor from hashed pending email and avoid writing raw email into new telemetry identifiers |
| T-23-03 | E | verify/resend route abuse handling | mitigate | Enforce OTP abuse cooldown before verify/resend processing and sync the same cooldown back to `OtpChallenge.locked_until` |
| T-23-04 | R | abuse cooldown auditing | mitigate | Persist cooldown decisions through the existing `AntiSpamEvent` and `AntiSpamActorState` tables for later inspection |
</threat_model>
